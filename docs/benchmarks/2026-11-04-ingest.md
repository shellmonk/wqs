# Ingest benchmark, 2026-11-04

Run with `./gradlew benchmark` (opt-in, `src/test/java/wqs/benchmark/IngestBenchmark.java`).

20000 stream messages (70% in sessions of 10) into Postgres 16 in a container.

| batch size | seconds | messages / s |
|---:|---:|---:|
| 1 | 31.5 | 635 |
| 500 | 18.3 | 1092 |

Batching removes the per-message commit, but each message still makes about four round trips
(row insert, session upsert, play upsert, play count), and those now dominate. At 1,092 messages/s
a 150M-event replay takes about 38 hours. Collapsing them into set-based statements per batch (one
batched insert, one upsert per session and play touched) is the next lever if replay speed matters;
over a real network to Aurora each round trip costs more, so the gain would be larger there.
