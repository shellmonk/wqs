# WQS Phase 4 — Level-0 Read Path Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve `GET /web/v1/projection` and `GET /cc/v1/projection` at aggregation level 0 with exact totals (range decomposition) and exact page numbers (counter-assisted offset), proven by P-3, P-5, P-6 and the §9 security test; plus the two Phase-4 items deferred from phases 1–3 (consumer start-failure policy, broker → tables end-to-end test).

**Architecture:** A reader-bound `DSLContext` (separate Hikari pool, read-only, REPEATABLE READ) serves every read inside one transaction, so the total and the slice see one snapshot. A pure `RangeDecomposition` splits `[from, to)` into newest-first segments (whole months → `"wqCountMonth"`, whole days → `"wqCountDay"`, boundary-day remainders → live COUNT). The offset walk subtracts segment counts to find the segment holding the page's first row, then runs ONE ordered key query from that segment's end down to `from` with the small residual offset, followed by a payload fetch by key. One query class per view (`wqs.read.web`, `wqs.read.cc`), per spec §2.2 rule 4.

**Tech Stack:** Java 21, Spring Boot 3.4.1 MVC, jOOQ 3.19.16, Flyway, HikariCP, MapStruct 1.6.3, Micrometer, jqwik 1.9.2 + jqwik-spring, ArchUnit 1.3.0, Testcontainers (Postgres 16, RabbitMQ), RabbitMQ stream client 0.18.0.

**Spec:** `docs/superpowers/specs/2026-10-31-wallet-query-service-design.md` — §7.1, §7.5–7.10, §8.1 (P-3, P-5, P-6), §8.5, §9, §10, §11.2. Rulings from phases 1–3: `docs/superpowers/plans/2026-11-02-wqs-phases-1-3-rulings.md`.

## Global Constraints

- All timestamps UTC; counter periods are UTC days and months (spec §7.1).
- Range is half-open `[from, to)`; `page` is 1-based; `totalPages == ceil(totalItems / pageSize)`, `0` when `totalItems == 0` (§7.1).
- Sort order fixed newest-first. Total order = `"occurredAt" desc, "itemId" desc` (the PK `("userId","occurredAt","itemId")` scanned backwards). Ties on `"occurredAt"` MUST be broken by `"itemId"` or P-3/P-6 are undefined.
- No cap on the `from`/`to` span (§7.1). Page size has no hard maximum; a configurable ceiling exists and ships **disabled** (§7.9).
- A page beyond the last page returns **200** with an empty `items` array and correct totals (§7.9).
- Level-0 counter semantics (match `CounterUpdater` / `ProjectionInvariants`): ITEM counters count every item row in the view's item table, cancellation rows included; `"cntExclCancelled"` counts rows with `not "cancelled"`. `"productId" = 0` is the all-products sentinel; rows with null product are counted only under the sentinel.
- jOOQ rules §2.2: no plain-SQL API outside `@RawSqlJustified` classes; jOOQ and generated types never in `api/` or `domain/`; generated `Record`s never returned upward; one query class per (view, level).
- MapStruct rules §2.3: mappers in `read/`, `unmappedTargetPolicy=ERROR` (already a compiler arg), `"detail"` mapped by an explicit named method.
- `/web` must never read `userId` from the request (§9).
- Database identifiers are camelCase and must be double-quoted in DDL and raw SQL (`checkMigrationQuoting` enforces it in migrations).
- Every ArchUnit rule carries a comment naming the spec decision it enforces (§8.5 governance), and every NEW rule must be proven able to fail (a fixture it rejects) — phases 1–3 shipped 13+ hollow tests/rules.
- Logging: `userId` as an identifier only; never log amounts, balances or `"detail"` at INFO (§11.4).
- Test Hikari pools stay small: the suite caches many Spring contexts against one Postgres (100 connections).

## Decisions made for this plan (user opted out of brainstorming)

| # | Decision | Why |
|---|---|---|
| D1 | Mixed-currency sessions keep `LEAST` (unchanged). Level 0 returns each item's own currency, so Phase 4 is unaffected; the open decision stays recorded for Phase 5. | User chose "skip questions"; L0 has no session rows. |
| D2 | `PrincipalResolver` with two modes: `none` (default — every `/web` request is 401) and `trusted-header` (reads `X-Authenticated-User-Id`, the gateway-injected option of O-2). | Secure by default: a header stub left on in production would let any client pick a user. |
| D3 | Consumer start failure **self-heals**: the app starts and serves reads; the consumer enters its existing recovery/backoff loop until the broker is reachable. | Reads must not depend on the broker once the app serves traffic. |
| D4 | Levels 1 and 2 return **501 Not Implemented** until Phase 5. | Parameter is mandatory (§7.1) and valid; the feature is absent. |
| D5 | `productId <= 0` is rejected with 400. | `0` is the counter sentinel; a client passing it would get sentinel totals but an empty `productId = 0` slice. |
| D6 | `from > to` → 400; `from == to` → 200, empty, totals 0. | Half-open empty interval is well defined. |
| D7 | The page-size ceiling, when enabled (`wqs.read.max-page-size`), **clamps**; the response reports the effective `pageSize`. | §7.9 "operations can clamp it". |
| D8 | Offset walk granularity is every segment (month, day, live remainder), not months only; after the walk, ONE ordered key query runs from the target segment's end to `from` (partition pruning + Merge Append handle the "continue into the next older month" case). | Finer residuals; one query regardless of how many sparse segments the page straddles. |
| D9 | Covering indexes include only what level-0 and high-level filtering reads: items `("userId","occurredAt" desc,"itemId" desc) include ("cancelled","productId")`; high-level per §5.6. | §7.7 says "conceptually"; YAGNI on columns no query filters by. |
| D10 | The §8.5 rule "production code must not depend on the naive-OFFSET oracle" is NOT added: the oracle lives in test sources, which main cannot compile against, and the importer excludes tests — the rule could never fail. | Hollow-rule lesson from phases 1–3. |
| D11 | The §8.5 rule "only projection/ may inject the writer DSLContext" is adapted: the writer is the unqualified primary `DSLContext` (ingest, db, jobs also write), so the enforceable rule is "every `DSLContext` injected into `wqs.read..` is `@ReaderDsl`-qualified". | Spec's intent (§10): a read must never silently land on the writer. |
| D12 | `/cc` has no authentication in this phase (spec defines none); recorded as a new open question. | Out of spec scope; surfaced, not invented. |

## Review Focus

1. **Ties on `"occurredAt"` straddling a page boundary** — many items sharing one timestamp must page without duplicates or gaps. Pinned in Task 5's generator (deliberate ties) and Task 4's `slice_orders_ties_by_itemId_desc`.
2. **Range bounds exactly on a day/month boundary, and data exactly on a boundary** — `to = 2034-02-01T00:00Z` must exclude an item at that instant; `from` at the same instant must include it. Pinned in Task 3 unit tests and the Task 5 generator's boundary-instant pool.
3. **`page * pageSize` overflow** — `page=2147483647&pageSize=2147483647` must return 200 empty with correct totals, not a negative offset or 500. Pinned in Task 6 (`far_beyond_last_page_is_empty_not_an_error`).
4. **`/web` with a `userId` query parameter, with and without a principal** — the parameter is ignored; without a principal the answer is 401, never another user's data. Pinned in Task 7.
5. **A range over months with no partitions (e.g. 1990 → 2100)** — must return 200 with correct totals, not an error about missing relations. Pinned in Task 6 (`range_far_outside_provisioned_partitions_is_fine`).
